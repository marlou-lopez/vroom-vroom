# Codebase audit, November 2026

Audit of the repo against current best practices (#64), done on 2026-11-05 while the codebase is
frontend only (~9,900 lines in `frontend/src`, 25 test files, 229 tests). Repeat for `backend/` once
Tasks 1–13 exist.

**Severity:** *High* breaks correctness or loses data; *Medium* a visible gap users or contributors
hit; *Low* cleanup or a guardrail. Every finding below was checked against the code or a command
run; the commands are listed at the end.

## Summary

The frontend is in good shape for its size. The API boundary is clean, the hot paths are
imperative and allocation-light, WebGL resources are disposed, and `src/lib` is well tested.
The gaps are mostly around the edges: keyboard access to the coach's cards, resilience when
something fails to render or load, per-frame re-rendering, and the absence of CI.

No High findings.

## Findings by area

### TypeScript
- `strict` is not set; `tsc --strict` reports 0 errors, so it can be turned on at no cost (#74).
- `noUncheckedIndexedAccess` would report 522 errors, mostly typed-array indexing in the hot
  paths. Not worth it now.
- No `any` outside tests. 55 `as` casts and about 16 non-null assertions, mostly at Radix
  `onValueChange` strings and three.js attribute types. Acceptable; the Radix ones could use small
  type guards when touched.
- One justified `oxlint-disable-line react-hooks/exhaustive-deps` in
  `state/useTelemetryData.ts:47` (memo on the parts of a computed object), with a comment.
- `api/types.ts` and the mock agree: the mock is written against the `Api` interface, and
  `api/realApi.msw.test.ts` runs the HTTP client against the mock handlers.

### React
- No error boundary (#70). No `Suspense`; loading states are explicit `Loading…` messages, which is
  fine with TanStack Query.
- Per-frame work is done right in most places: `DetailedStrips` and `DetailedMapView` subscribe to the
  playback store and update imperatively. The exception is `TrackPanel` (#69). `Transport` also
  re-renders per frame (the clock and corner ticks), which is cheap; its scrubber layers are passed
  as stable elements, so they don't re-render.
- Large components: `DetailedMapView.tsx` (~700 lines, #77), `DetailedStrips.tsx` (370),
  `TracksPage.tsx` (272).
- No 404 route: an unknown path renders the shell with an empty page. Minor; not filed.

### State and data
- Components reach data only through `api` and the query hooks; no component imports mock data
  (only tests and `api/mock/handlers.ts` do). The `Api` boundary holds.
- Query keys come from one factory (`qk` in `api/queries.ts`). `usePatchLap` invalidates laps,
  comparisons and candidates but not session summaries, which depend on validity. Not visible today
  (Sessions is its own route and `staleTime` is 0, so it refetches on mount); noted in #78.
- The playback store is a small vanilla Zustand store behind context, with selector subscriptions
  and a capped `dt` in the rAF loop. Good shape.
- Client-generated landmark ids (#76).

### WebGL / three.js
- `webglRenderer.ts` disposes line geometries on scene change and all geometries and materials in
  `destroy()`, then forces context loss and removes the canvas. Late renderers (promise resolving
  after unmount) are destroyed.
- Context loss is handled (status box, auto-restore by rebuilding, Retry after 3 s). A renderer that
  never starts is not (#71).
- Per-frame work: only the driven segment's end floats are re-uploaded (`addUpdateRange`); the
  gain line is rebuilt only when the zoom changes. One small array literal per frame for the chevrons;
  negligible.

### Performance and bundle
- Main bundle 469 KB (158 KB gzip): React, React Router, TanStack Query, Radix, uPlot.
- `webglRenderer` chunk 559 KB (139 KB gzip), lazy-loaded only for the detailed view. Vite warns
  that it's over 500 KB; three.js doesn't tree-shake well. Fine for a local app; raise
  `build.chunkSizeWarningLimit` with a comment if the warning gets noisy.
- The mock recording is shipped in production builds (#73).

### Accessibility
- Text contrast passes WCAG AA everywhere: muted text `#868E99` is 5.1–5.8:1 on the backgrounds,
  annotation colours 6.6–11:1, brake red `#F0504F` the lowest at 4.8–5.5:1.
- Non-text contrast: control borders (`#2A2F37`) and the map base line (`#23272E`) are about
  1.2–1.4:1, below the 3:1 guideline for UI components. Controls are still identified by their
  text, so this is a design trade-off of the dense dark theme; not filed.
- Focus ring is visible (`:focus-visible`, 2 px in the "you" colour, 11:1).
- Radix toggle groups, sliders and menus have `aria-label`s; the strips are a labelled focusable group
  with arrow-key scrubbing; the scrubber has `aria-valuetext`.
- Gaps: annotation cards (#68), landmark add (#75), and the detailed map pans and zooms by pointer
  only (Fit and Follow buttons cover the essentials; not filed).

### Tests
- Strong unit coverage of `src/lib` (camera, geo, racing line, track edges, strips, gain/loss,
  playback, sessions), the mock API (466-line test), the scene builder and the playback store.
- Missing: any DOM environment, hence every component and hook; a few pure modules (#78).

### Tooling and repo
- No CI (#72).
- `npm audit`: 0 vulnerabilities. Major versions available: React 19, TypeScript 7, MSW 3,
  `@types/node` 26. Nothing urgent; upgrade React and TypeScript deliberately, one at a time.
- Pinning is mixed (exact for most, `^` for React, React Router, Vite, Vitest and types). With the
  committed `package-lock.json` and `npm ci` in CI this is fine.
- Lint: oxlint with `react`, `typescript`, `oxc`; `exhaustive-deps` and the React-compiler rules are
  on. `jsx-a11y` is off (#74).
- `tools/extract-laps.mjs` opens its input with `access_mode: 'READ_ONLY'`, but doesn't copy it
  first as the recording rule asks, and its `@duckdb/node-api` dependency isn't pinned anywhere (#79).
- `.gitignore` covers `.env`, `node_modules`, `dist`, `*.duckdb` (except future backend fixtures)
  and Python caches.

### Security and privacy
- No secrets, API keys or absolute home paths in the tree or in git history (searched
  `git log --all -p`).
- The driver name was hard-coded in `api/mock/mockApi.ts` (two places). It's replaced with `"Driver"` on
  this branch. It still exists in commit `1d2d62d` and in the public fork's 2026-11-04 snapshot;
  rewriting history wouldn't reach the fork, so it's left as is. Commit author metadata carries the
  author's name and email, as in any git repo.
- The mock recording JSON contains no driver name.
- MSW is dev-only: `main.tsx` imports the worker dynamically when `VITE_API=mock`, and no mock
  code reaches `dist/assets`. Only the static files in `public/` leak into the build (#73).
- Fonts load from Google Fonts at runtime, so the app makes a third-party request on start. Not
  filed: acceptable for now. Self-hosting Inter and JetBrains Mono would make it work offline.

### Docs
- `CLAUDE.md` matches the code, except the lint note ("5 known React-compiler warnings, tracked in
  #26"): 2 of the 5 are not React-compiler warnings (#74 notes it).
- `docs/lmu-duckdb-schema.md` and `docs/track-views/` are current with the code they describe.
- README gaps (#79).

## How this was checked

Run in `frontend/` unless noted:

```bash
npx tsc -p tsconfig.app.json --noEmit --strict                              # 0 errors
npx tsc -p tsconfig.app.json --noEmit --strict --noUncheckedIndexedAccess    # 522 errors
npm audit; npm outdated
npm run build && ls dist dist/mock                                          # mock JSON + worker in dist
gzip -c dist/assets/*.js | wc -c                                            # per file
npx oxlint -c <config with jsx-a11y> src                                    # 4 hits
npm run test; npm run lint
git log --all -p | grep -E '/home/|/Users/|sk-ant|API_KEY='                # repo root: nothing
git log --all -S'<driver name>' --oneline                                   # repo root
```

Contrast ratios were computed with the WCAG 2.1 relative-luminance formula from the tokens in
`src/theme.ts`.
